# Установка Seller Analytics Bot на аккаунте клиента

Для версии 1.0.4. Клиент владеет Telegram-ботом, аккаунтом хостинга, данными и ключами маркетплейсов. Один независимый продавец — отдельный экземпляр и база. Сотрудники одного продавца получают роли внутри его бота.

## 1. Подготовьте аккаунты

1. Клиент создаёт Telegram-бота у [@BotFather](https://t.me/BotFather): `/newbot`, название и уникальный username. Токен вводит в закрытые настройки хостинга.
2. Подготовьте числовой Telegram ID владельца. Его показывает, например, [@userinfobot](https://t.me/userinfobot). Marketplace-токены этому боту не передавайте. ID — число, а не `@username`.
3. Клиент регистрируется в Bothost на свою почту и оплачивает выбранный тариф самостоятельно. Проверьте цену, постоянное хранилище и непрерывную работу на странице тарифов перед покупкой.
4. Подготовьте API-права WB/Ozon по `docs/USER_GUIDE_RU.md`. WB нужен доступ к «Аналитике» для воронки заказов; остальные категории зависят от подключённых функций. Для рекламы Ozon нужны отдельные реквизиты Performance, Seller API их не заменяет.

## 2. Выберите источник кода

Для рабочих установок удобно иметь отдельную ветку `production` в копии репозитория клиента. Обновляйте её вручную после проверки выпуска. Не привязывайте все клиентские установки к автоматически обновляющейся разработческой `main`.

Git-путь: клиент создаёт пустой репозиторий в своём аккаунте, загружает файлы проверенного ZIP (включая `.env.example` и `.dockerignore`), затем подключает репозиторий в Bothost. Приватный репозиторий подключается по инструкции самого Bothost. В корне должны лежать `main.py`, `requirements.txt` и `Dockerfile`; папки `app`, `scripts`, `docs` сохраняются целиком. Файлов `.env`, готовой БД и чужих выгрузок в поставке быть не должно.

Архив-путь: Bothost также поддерживает загрузку ZIP на тарифах Базовый/Pro, но в проверенной документации функция ограничена тестовой нодой. Откройте профиль → «Интерфейс» → «Загрузка бота из архива», сохраните; в «Мои боты» выберите «Загрузить из архива». Загрузите выпуск и укажите `main.py`. Если функция недоступна, используйте Git-путь. Обновления архивной установки выполняются новым ZIP, Git-установки — через Git.

## 3. Создайте бота в Bothost

1. Откройте создание бота; выберите Telegram, Python/aiogram, свой репозиторий и рабочую ветку либо мастер архива.
2. Укажите точку входа `main.py` и Python 3.11 или новее; используйте поставленный Dockerfile.
3. В закрытых переменных окружения добавьте параметры из таблицы. Если первая сборка запустилась до добавления переменных и остановилась с сообщением об обязательном токене/owner ID, это устраняется сохранением env и перезапуском.

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота клиента |
| `TELEGRAM_OWNER_ID` | Числовой Telegram ID владельца; несколько system owners — через запятую |
| `DB_FILE` | `/app/data/seller_analytics.sqlite3` для новой установки |
| `TIMEZONE` | `Europe/Moscow` |
| `REPORT_TIME` | `09:00` |
| `WB_API_TOKEN` | Ключ WB клиента, если WB подключается |
| `OZON_CLIENT_ID` | Client ID Ozon клиента, если Ozon подключается |
| `OZON_API_KEY` | Seller API key Ozon клиента |
| `OZON_PERF_CLIENT_ID` | Performance client ID, если нужна рекламная статистика Ozon |
| `OZON_PERF_CLIENT_SECRET` | Performance client secret |
| `AUTO_BACKUP_ENABLED` | `true` |
| `BACKUP_RETENTION_DAYS` | `14` |
| `AUTO_BACKUP_SEND_TELEGRAM` | `false`; `true` — только если владелец согласен получать всю БД в Telegram |

Имена переменных должны совпадать с таблицей. Примеры `DB_PATH`/`DATABASE_PATH` из общей документации Bothost к этому проекту не относятся: здесь используется `DB_FILE`. База создаётся автоматически. Для уже существующей установки сохраните её путь и имя.

Секреты клиент вводит в панель самостоятельно. При подключении под ключ используйте ограниченное временное приглашение в хостинг/репозиторий, если платформа его поддерживает, или совместную демонстрацию экрана. После передачи клиент отзывает ваш доступ. Обычных сотрудников не добавляйте в `TELEGRAM_OWNER_ID`: system owner имеет доступ к бэкапу всех магазинов.

## 4. Запустите и настройте

1. Пересоберите и запустите бот. Дождитесь успешного старта в логах. Не запускайте два экземпляра с одним Telegram-токеном.
2. В Telegram владельца нажмите Start → «🏪 Магазин» → «🧩 Мастер настройки». Укажите название, часовой пояс, время отчёта и пороги. После завершения параметры магазина сохраняются в БД; последующая смена `REPORT_TIME` в env не заменяет настройки уже настроенного магазина.
3. Нажмите «🔌 Проверить API» и «✅ Что настроено». Исправьте права/токены в env и перезапустите, если проверка не прошла.
4. Проверьте, что демо выключено перед реальным подключением. Демо предназначено для отдельного пустого тестового магазина.
5. Откройте «📊 Отчёты» → «📥 Догрузить данные»: выберите площадки и 7–14 завершённых дней. Для начального анализа поставок постепенно загрузите 28–56 дней; короткая история ограничивает уверенность прогноза. Не запускайте параллельные загрузки; лимиты API могут удлинить ожидание.
6. В «💰 Деньги и реклама» нажмите «🔄 Обновить все отчёты» и отправьте `1 YYYY-MM-DD` с завершённым проверочным днём. Дождитесь результатов источников.
7. Сверьте WB по тому же дню и фильтрам воронки; Ozon — отдельно число/стоимость заказов и финансовые начисления после удержаний. «🧮 Начисления Ozon» выгружает операции CSV для проверки. Расхождение с бухгалтером требует одного исходного отчёта и методики; его нельзя исправлять подстановкой желаемой суммы.
8. Импортируйте подготовленную историю себестоимости через «📦 Товары» → «📥 Импорт себестоимости». Поля и образец бот показывает перед загрузкой. Укажите реальную дату действия цены, особенно при пересчёте прошлого периода.
9. Обновите текущие остатки, поставки в пути и акции соответствующими кнопками. Отчёт по поставкам используется как рекомендация, закупки автоматически не выполняются.

## 5. Выдайте доступ сотрудникам

Сотрудник открывает этого Telegram-бота и нажимает Start: бот показывает его Telegram ID. Владелец выбирает магазин → «Сотрудники» → «Открыть» → «Добавить сотрудника», отправляет числовой ID и выбирает роль кнопкой.

| Роль | Права |
| --- | --- |
| Менеджер (`manager`) | Продажи, товары, остатки, реклама, поставки и их обновление; экспорт рабочих данных. Финансы закрыты, настройки только для просмотра |
| Бухгалтер (`accountant`) | Рабочие и финансовые отчёты, себестоимость, импорт и рабочие настройки; сотрудники и технические функции закрыты |
| Владелец (`owner`) | Все рабочие функции и управление сотрудниками своего магазина |

Для изменения нажмите на человека → «Изменить роль»; для удаления → «Отозвать доступ» и подтвердите. Права задаются отдельно для каждого магазина. Команды также работают: `/user_add TELEGRAM_ID manager Имя`, `/user_remove TELEGRAM_ID`. Последнего владельца нельзя удалить или понизить. Общая БД, диагностика и API-подключения доступны владельцу установки из `TELEGRAM_OWNER_ID`.

## 6. Принимайте установку по результату

Установка считается переданной после проверки следующего: владелец получает отчёт; API-права проверены; выбранный день сверён по согласованному источнику; отсутствие себестоимости видно в покрытии; сотрудник видит только разрешённый магазин; бэкап скачан; перезапуск не очистил историю; клиент знает порядок обновления и контакты поддержки.

Сохраните в карточке клиента версию, дату запуска, перечень подключений, согласованную методику суммы и состояние проверки. Токены в карточку не записывайте.

## 7. Обновляйте и сохраняйте данные

Перед новым выпуском создайте `/backup` и скачайте файл. Обновите код существующего бота из своего Git либо новым архивом согласно типу установки; сохраните env и путь `DB_FILE`. Затем `/health` → `/connect_check` → полное обновление одного дня → сравнение отчёта. Для 1.0.4 порядок подробно описан в `UPDATE_1_0_4_RU.md`.

Ежедневный локальный backup не защищает от потери аккаунта/диска хостинга. Сохраняйте копию на другом устройстве или включите отправку system owner в Telegram. Большие копии сжимаются в ZIP; если файл не отправляется, бот сообщает путь к оригиналу на сервере. Проверяйте восстановление через `/restore` на отдельном тестовом боте: загрузка файла запускает проверку и замену базы со страховочной копией. Принимается SQLite или ZIP с одним SQLite-файлом: загрузка до 20 МБ, распакованная база до 200 МиБ. Для больших файлов используйте файловый доступ к остановленному серверу. В тестовой копии отключите фоновые алерты/рассылки и используйте другой Telegram-токен.

## Что зависит от внешних сервисов

Работа требует оплаченного и доступного хостинга, действующих API-прав и доступа к Telegram. Маркетплейсы могут запаздывать и корректировать финансовые данные. История себестоимости нужна для управленческой оценки; налоги, общие расходы бизнеса и бухгалтерская чистая прибыль в неё автоматически не включены. Стоимость самой поставленной версии и условия будущих обновлений/поддержки согласуются отдельно.
