# Обновление 1.0.6 и сверка суммы заказов Ozon

В ежедневном и товарном отчётах сумма заказов Ozon явно подписана «по предельной цене». Ежедневный отчёт указывает соответствующую колонку личного кабинета для сверки. Это уточнение смысла уже загружаемого показателя `revenue` из аналитики API.

## Три разных показателя

- Сумма заказов по предельной цене — денежная метрика заказов, которую сейчас получает бот из аналитики API.
- Сумма заказов по цене реализации — отдельная метрика кабинета по цене покупки товара клиентом. Текущий сбор бота не загружает её отдельным показателем.
- Начисления после удержаний — сумма финансовых операций по дате начисления. В неё могут входить заказы других дат.

Цена реализации не рассчитывается вычитанием комиссий, логистики, рекламы или себестоимости из суммы новых заказов. Для её автоматического добавления нужен подтверждённый источник именно этой метрики за ту же дату и тот же набор товаров.

## Обновление Bothost

1. Создайте резервную копию командой `/backup` и сохраните полученный файл.
2. Обновите исходники из репозитория и выполните rebuild на Bothost.
3. После запуска откройте отчёт по загруженной дате. Сумма Ozon должна иметь подпись «по предельной цене»; начисления показаны отдельной строкой с копейками.

Новых переменных окружения и миграций БД нет. API-запросы и финансовые формулы прежние; сохранённые значения не переписываются обновлением подписей.

## Проверка без платной выгрузки

1. В боте выполните `/refresh 1 YYYY-MM-DD` за выбранный завершённый день и дождитесь результата для заказов Ozon.
2. В Ozon откройте «Аналитика» → «Моя аналитика» и выберите точно тот же день и тот же набор товаров и схем работы.
3. Сравните количество товаров и колонку «Заказано на сумму (по предельной цене)» с ботом. Колонку «по цене реализации» сравнивайте отдельно.
4. Для диагностики достаточно скрина итогов и резервной копии бота после сбора. Скрины товарных строк дополнительно позволяют сопоставить товары, количество и обе суммы без скачивания платной выгрузки.

Отображаемые суммы на скринах приведены к целым рублям. Если сумма видимых строк отличается от итоговой строки, для проверки копеек понадобятся исходные значения до отображения; округлённые строки не следует подгонять под итог.
