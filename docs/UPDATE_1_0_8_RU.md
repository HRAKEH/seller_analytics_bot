# Обновление до 1.0.8: цена покупателя в деталях FBO

Бот дополнительно получает финансовые данные каждого отправления FBO. В документации Ozon поле `customer_price` предусмотрено в ответе отдельного отправления; в списке FBO его нет. Полные ответы сохраняются для сверки и входят в обычный бэкап. Итоговые денежные показатели пока используют проверенные источники аналитики и начислений.

## Что нажать

1. Сохраните текущую базу командой `/backup`.
2. В Bothost обновите проект из ветки `main` и сделайте ребилд. Сохраните существующие переменные окружения и постоянный каталог базы.
3. После запуска отправьте `/diagnostics`. Схема остаётся **15**; релиз **1.0.8** указан в файле `VERSION` репозитория.
4. Отправьте `/refresh 1 2026-10-01`. Команда повторно загружает выбранную дату, даже если она уже была сохранена. Для другого завершённого дня замените дату.
5. Дождитесь итогового сообщения. Загрузка деталей FBO входит в этап **«Отправления Ozon · FBO/FBS»**. Если стоит `⚠️`, сохраните сообщение и `/diagnostics` вместе с новым бэкапом: успешно полученные данные всё равно сохраняются.
6. Отправьте `/backup` и скачайте новый `.sqlite3`. Старый бэкап или создание бэкапа до завершения обновления не дадут новых деталей.

Тот же запуск через кнопки: **«💰 Деньги и реклама» → «🔄 Обновить все отчёты»**, затем `1 2026-10-01`. Для точного выбора даты удобнее команда выше. Отдельный ребилд перед каждым обновлением данных не требуется.

Один запрос выполняется для каждого уникального отправления FBO, поэтому большие диапазоны обновляются дольше. Для первой сверки достаточно одного дня. Токен не нужно перевыпускать только из-за обновления сборки; если API откажет в доступе, ответ будет зарегистрирован.

## Что будет в бэкапе

- Списки FBO/FBS сохраняются в прежних источниках `postings/fbo` и `postings/fbs`.
- Детали FBO сохраняются отдельно: `source_runs.endpoint = postings/fbo/details`, исходный JSON — в `raw_payloads.payload_json`.
- `list_source_run_id` указывает на список FBO, по которому сделаны запросы. Дата деталей соответствует московскому дню заказа из этого списка, даже если временные поля ответа деталей отличаются.
- `request_endpoint` и `request_with` показывают использованный метод `/v2/posting/fbo/get` и запрос `financial_data=true`.
- `expected_postings` содержит уникальные номера из списка; `requested_postings` — номера фактически запрошенных отправлений. Дубликаты одного номера не вызывают повторных запросов; разные отправления одного заказа запрашиваются отдельно. Отменённые отправления тоже сохраняются.
- `responses` содержит номер отправления, HTTP-код и полный исходный `response`, включая `result.financial_data.products[].customer_price`, `customer_currency_code` и неизвестные поля, если Ozon их вернул.
- `errors` содержит неуспешные и пропущенные запросы. Ошибочный номер отправления в ответе не принимается за цену нужного заказа. После окончательной ошибки 401/403/429 оставшиеся запросы деталей в текущем диапазоне пропускаются; новый запуск может повторить загрузку.
- `complete=true` и статус `success` означают получение корректных ответов для всех ожидаемых отправлений. При ошибках сохраняется `complete=false`, статус `partial` и все уже полученные ответы. Предыдущие успешные загрузки остаются в истории; текущая неполная загрузка не выдаётся за успешный снимок.
- Отдельные ошибки API записываются как `postings/fbo/get` с исходным HTTP-кодом и очищенным от ключа API сообщением. Пустой день сохраняется как полный пустой снимок без запросов отдельных отправлений.

`✅` в итогах обновления и `complete=true` подтверждают успешное получение ответов, но не гарантируют наличия цены покупателя у каждого товара. Ozon может вернуть `financial_data=null` или не заполнить цену. Такие ответы сохраняются без подстановки нуля. Настоящий ноль сохраняется как ноль; сумма в BYN сохраняется в BYN и не складывается с RUB.

Новые таблицы и миграции не нужны. Цены деталей не подставляются вместо предельной цены, выплат или начислений. После сверки фактических ответов можно выбрать формулу нового показателя. Способ получить точный рублёвый эквивалент валютного заказа, совпадающий с аналитикой кабинета, пока не подтверждён.
