# Большие резервные копии

При создании копии бот уплотняет только скопированную SQLite-базу, освобождая неиспользуемые страницы, и использует ZIP/Deflate уровня 9. Данные и рабочая база не удаляются. При отправке существующего архива больше 45 МиБ бот пробует ZIP/LZMA и проверяет целостность. Более сильное сжатие может занимать время; сетевой цикл бота не блокируется.

Если файл всё ещё большой, бот присылает части `.001`, `.002` и далее, каждая не больше 45 МиБ, и файл `RESTORE.txt`. Это работает при ручной отправке, отправке последней копии и автоматической отправке. Дополнительные переменные не нужны. Автоматическая отправка по-прежнему включается отдельно через `AUTO_BACKUP_SEND_TELEGRAM=true`.

Сохраните все части в одну папку без переименования. В приложенном `RESTORE.txt` есть точная команда `copy /b` для Windows cmd и SHA-256 объединённого файла, а также размеры и хеши частей. Можно открыть `.001` через 7-Zip. ZIP/LZMA также открывайте через 7-Zip. Части — один архив, а не самостоятельные резервные копии.

Отдельные части не принимаются командой `/restore`. Бот может скачать из Telegram только файл до 20 МБ; для встроенного восстановления действует также ограничение распакованной базы в 200 МиБ. Большую собранную базу восстанавливайте через файловый доступ хостинга: остановите бота, сохраните рабочую базу вместе с существующими WAL/SHM отдельно, распакуйте копию, замените файл по `DB_FILE`, уберите прежние WAL/SHM из рабочей папки и затем запустите бота. Не заменяйте базу работающего процесса.

Исходная проверенная копия остаётся на сервере и защищена от очистки во время отправки; временные архивы и части удаляются после завершения или ошибки. Если передача оборвалась, запросите последнюю копию повторно и используйте один полный набор из одной отправки. Если не хватает места для подготовки частей, бот сообщит путь сохранённого файла; скачайте его через панель хостинга.
