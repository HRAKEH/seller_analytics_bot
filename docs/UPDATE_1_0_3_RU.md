# Обновление Bothost до 1.0.3

## Перед обновлением

1. В Telegram выполните `/backup` от системного владельца бота. Скачайте полученную копию БД на компьютер. Команда `/backups` показывает сохранённые резервные копии.
2. В Bothost запишите текущий путь `DB_FILE` и проверьте, что этот файл находится в постоянном хранилище. Сохраните текущие переменные окружения и настройку подключения диска.
3. Проверьте `WB_API_TOKEN`: для новой воронки нужна категория «Аналитика», для резервных заказов — «Статистика». Для остальных функций бота также нужны «Финансы», «Продвижение», «Поставки», «Цены и скидки». Токен с выбранными категориями с вашего скрина подходит; значение токена вводится только в переменные Bothost. Если в используемом токене нет нужной категории, создайте новый токен и замените значение. Перезапустите бота после изменения переменных.

## Установка

1. Остановите текущий процесс бота в Bothost.
2. Загрузите код из `seller_analytics_bot_1.0.3.zip` вместо предыдущей сборки. В корне приложения должен остаться `main.py`; запуск — `python main.py`. Установите зависимости из `requirements.txt`, если хост не делает этого сам.
3. Сохраните прежние `DB_FILE`, подключённый постоянный диск и переменные окружения. Сборка не содержит рабочую БД. Если пересоздание приложения удаляет локальные файлы, предварительно перенесите БД в постоянное хранилище или восстановите скачанную копию в указанный `DB_FILE`.
4. Запустите один процесс бота. Схема остаётся 15; магазин, сотрудники, себестоимость и история сохраняются при использовании прежней БД.
5. Выполните `/settings` и `/connect_check`. Проверка подключений проверяет категории и доступы; первый запрос `/day` дополнительно проверит доступ к конкретному API воронки.

## Проверка 30 сентября

1. Выполните `/finance 1 2026-09-30`. Команда обновляет финансы ровно за 30 сентября. Для обновления API нужна роль analyst/owner; viewer видит сохранённые данные.
2. Затем выполните `/day 2026-09-30`. В строке WB ожидается `источник: Воронка продаж`. Сверяйте число и стоимость заказов с WB → «Аналитика» → «Сводка»: 30 сентября, оба склада, без фильтров по товарам. На вашем снимке — 128 шт. / 101 350 ₽. Это ориентир сверки, а не число, подставленное в код: итог поступает из API и может меняться при обновлении данных WB.
3. Если WB показывает `Статистика, резервный источник`, проверьте сообщение об ошибке и токен. При уже сохранённой воронке бот сохраняет её последний успешный итог и показывает ошибку обновления; оперативная статистика его не заменяет.
4. Ozon показывает отдельно стоимость заказов до удержаний и начисления после удержаний. В предоставленных БД и XLSX за 30 сентября финансовый итог совпал: **13 570,60 ₽**. Реклама **2 482,42 ₽** входит в удержания. Новый живой ответ может включать более поздние корректировки.
5. Число 38 шт. относится к заказам дня. Финансовые начисления дня включают продажи более ранних дат, поэтому делить нетто на эти 38 шт. как цену реализации нельзя. **17 159 ₽** пока не подтверждены присланным отчётом; у бухгалтера нужен исходный отчёт/экран и применённые фильтры.

## История и управленческий расчёт

- `/backfill 7 wb` обновляет прошлые семь завершённых дней по воронке, включая дни, ранее загруженные через статистику. Для сопоставления двух недель используйте `/backfill 14 wb`. Уже загруженные дни воронки повторно через backfill не запрашиваются; отдельную дату можно освежить через `/day YYYY-MM-DD`.
- У воронки лимит запросов: бот выдерживает интервал 20 секунд. Семь дней могут загружаться несколько минут, особенно при большом числе карточек. Дождитесь завершения; в меню загрузки доступна отмена.
- Проценты роста WB в дневном, периодном и товарном отчётах скрываются, если сравниваемые дни используют разные источники. Обновление обеих частей истории возвращает сравнение.
- `/finance 7` обновляет последние семь завершённых дней. В `/management 7` начисленная реклама вычитается один раз. Performance за дни с начислениями показан справочно, за дни без начислений используется предварительно.
- Сумма после удержаний — начисления маркетплейса, а не бухгалтерская чистая прибыль или банковская выплата. Для оценки себестоимости нужна заполненная история стоимости товаров.

Обновлённые формулы: `docs/FORMULAS_RU.md`. PDF-документы предыдущего выпуска сохраняют прежнюю версию; для изменений 1.0.3 используйте этот файл и актуальный Markdown с формулами.
