# Обновление до 1.0.20

1. Создайте резервную копию через **Ещё → Техническое → Создать backup** и сохраните файл.
2. В BotHost выполните ребилд ветки **main**. После запуска: версия **1.0.20**, схема **21**. Базу и переменные хостинга сохраните; для этого обновления токены менять не нужно.
3. Откройте **Отчёты → Вчера** и нажмите **Обновить**. Старое сообщение также можно обновить этой кнопкой; новую дату выбирайте в календаре под карточкой.

## Что изменилось

- Один ежедневный блок: заказано, выкуплено, возвращено, отменено отдельно для WB и Ozon. Общий итог относится только к заказам. Суммы после удержаний — в прежних начислениях.
- WB: продажи и возвраты по полю `date`, отмены по `cancelDate`. Отмена вчерашнего заказа сегодня больше не выдаётся за отмену вчера. Сумма продаж/возвратов берётся из `finishedPrice`, без подстановки цены со скидкой продавца; незаполненные цены дают предупреждение.
- Ozon: клиентские возвраты FBO/FBS по `logistic.return_date` и количеству товаров. Отказы при вручении, технические возвраты и движение возврата на склад не выдаются за клиентские возвраты после продажи.
- Выкупы Ozon читаются из отдельного отчёта о реализации за день. Он требует Premium Plus/Pro, доступен за последние 32 календарных дня и может не возвращать подтверждение валюты. Без полного доступа/количества/цены соответствующий итог не рассчитывается. Бот не использует для него статусы отправлений, созданных в этот день, или признак выкупа маркетплейсом.
- Общая дата всех отмен Ozon пока не подтверждена доступными источниками: в карточке будет явный пропуск с пояснением. Не ноль и не число отменённых заказов, оформленных в эту дату.
- **Выбрать дату**: календарь меняет карточку в одном сообщении и показывает сохранённые данные. **Обновить** загружает выбранный день. Длинные **Подробнее** и **Начисления** перелистываются. **Главное меню** возвращает к разделам.
- Новые источники подключены к ручному обновлению и ежедневному сбору. Права магазина проверяются при смене даты; менеджеру закрыты начисления. Отказ optional API не запускает повторную загрузку всех заказов и финансов. После изменения прав Ozon или подписки перезапустите бот, чтобы снять запомненный отказ доступа.
- **Полнота источников** показывает выкупы, клиентские возвраты и отмены отдельно. Полнота количества не гарантирует полноту денежных цен.

## Что проверить после ребилда

1. **Вчера → Обновить → Подробнее**: укажите одну дату и убедитесь, что видно время проверки каждого источника. Пропуски имеют причину.
2. Для WB сравните продажи/возвраты за день и отмены именно по дате отмены. Данные WB предварительные; цены могут дозаполняться позднее и отличаются от финансового отчёта.
3. Для Ozon сравните клиентские возвраты после вручения за тот же московский день. Отказы в ПВЗ проверяются отдельно. Если дневная реализация недоступна, это ожидаемый статус доступа, а не доказательство отсутствия выкупов.
4. Повторите обновление: количество не должно удвоиться. Откройте другую дату, вернитесь и проверьте подпись дня. Календарь сам не загружает маркетплейсы.
5. Отправьте свежий бэкап и цифры кабинета за один день для проверки на ваших данных. Локальные тесты не подтверждают совпадение с реальным кабинетом.

Официальные источники: [Ozon Seller API](https://docs.ozon.ru/api/seller/), [WB: продажи и возвраты](https://dev.wildberries.ru/openapi/reports), [WB: заказы](https://dev.wildberries.ru/openapi/reports). Нормализация использует сохранённую официальную схему Ozon API от 02.10.2026. Изменения базы не требуются.

Локальные проверки: **690 тестов прошли**, аудит релиза, компиляция, зависимости и preflight на отдельной базе успешны. Тесты проверяют алгоритмы и интерфейс на двойниках API/Telegram; реальная сверка кабинета ещё нужна.
