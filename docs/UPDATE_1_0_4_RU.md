# Обновление до 1.0.4 на Bothost

Версия 1.0.4, схема SQLite 15. Новая миграция БД не требуется. Данные, себестоимость и доступы сохраняются при использовании постоянной папки `/app/data`.

## Поочерёдно что нажать

1. В Telegram откройте «🛠 Ещё» → «🧰 Техническое» → «💾 Создать backup». Сохраните полученный файл на компьютере. Команда `/backup` доступна system owner из `TELEGRAM_OWNER_ID`.
2. В Bothost проверьте переменную `DB_FILE`: она должна указывать на вашу существующую базу в `/app/data`. Не меняйте имя существующей базы на имя новой: иначе бот создаст пустую БД.
3. Для текущего бота из Git нажмите обновление из репозитория и пересборку. Для бота, созданного из архива, загрузите новый архив через кнопку обновления архивного бота. Эти способы в Bothost различаются; Git-бот нельзя обновить загрузкой ZIP через архивный мастер.
4. Дождитесь успешного запуска. Проверьте логи и команду `/health`. Оставьте один работающий экземпляр на один Telegram-токен.
5. Нажмите «🏪 Магазин» → «🔌 Проверить API». Если изменились права или истёк токен, замените значение в окружении Bothost и перезапустите приложение. Обычная установка новой версии не требует выпускать новый токен.
6. Откройте «💰 Деньги и реклама» → «🔄 Обновить все отчёты». Отправьте `1 YYYY-MM-DD`, заменив дату нужным завершённым днём. Например: `1 2026-09-28`. Дождитесь результата всех этапов.
7. Нажмите «📡 Полнота источников» и отправьте тот же период. Если часть источников недоступна, бот сохранит предыдущие успешные данные и покажет предупреждение.
8. Нажмите «🧮 Начисления Ozon» и отправьте тот же период. Сверяйте CSV с отчётом бухгалтера по одной дате, кабинету, виду суммы и составу операций.
9. Дневной отчёт за ту же дату: «📊 Отчёты» → «🗓 Другая дата». Эта кнопка читает БД без новой загрузки API.

## Что обновляет полная загрузка

Заказы, начисления и удержания, рекламу, отправления Ozon и продажи/возвраты WB за выбранный период. Лимит одного запуска — 31 день. Бот выдерживает лимиты маркетплейсов; несколько дней могут загружаться долго. Ошибка одной площадки не отменяет сохранение успешной другой.

Остатки — текущий снимок, их обновляйте отдельно: «📦 Товары» → «🔄 Обновить остатки». Поставки в пути и акции обновляются в «🚚 Поставки». Новая версия не создаёт исторические остатки задним числом.

## Команды для выбранной даты

```text
/refresh 1 2026-09-28
/sources 1 2026-09-28
/accruals 1 2026-09-28
/finance 1 2026-09-28
/ads 1 2026-09-28
/management 1 2026-09-28
/sku_finance 1 2026-09-28
/reconcile 1 2026-09-28
```

`sources`, `accruals`, `sku_finance` читают сохранённые данные. Slash-команды `finance`, `ads`, `management`, `reconcile` для analyst/owner дополнительно вызывают соответствующие API; у viewer работают только на чтение. Для ежедневной работы после полной загрузки пользуйтесь кнопками чтения.

## Резервные копии

Автоматическая копия создаётся в `data/backups`. Для отправки дополнительной копии в Telegram задайте `AUTO_BACKUP_SEND_TELEGRAM=true` и перезапустите бот. Копию получают только system owners; в ней данные всего экземпляра. Каждый получатель заранее нажимает Start. Файлы свыше 45 MiB скачиваются через панель хостинга. Сохраняйте копии отдельно и проверяйте восстановление на отдельном тестовом боте.

## Пределы расчёта

Начисления после удержаний не равны выплате на банк или чистой прибыли. Себестоимость влияет на оценку результата, но не на заказы и исходные начисления API. Для оценки нужна история себестоимости с правильной датой начала. Неизвестные расходы не распределяются по товарам без источника. Финансовые операции могут относиться к заказам прежних дней; бухгалтерскую чистую прибыль бот не обещает.

Источники устройства Bothost, проверены 01.10.2026: [постоянное хранилище](https://bothost.ru/docs/database-storage), [обновление архивного бота](https://bothost.ru/docs/upload-bot-archive).
