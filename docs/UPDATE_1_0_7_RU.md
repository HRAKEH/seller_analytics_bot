# Обновление до 1.0.7: финансовый блок отправлений Ozon

Бот запрашивает дополнительный блок `financial_data` в списках отправлений FBO и FBS на каждой странице. Ответ сохраняется в существующей SQLite-базе и входит в обычную резервную копию. Это сбор данных для проверки цены реализации; автоматический расчёт нового показателя будет зависеть от фактически полученных полей и результатов сверки.

## Обновление и проверка выбранного дня

1. Создайте текущий backup командой `/backup` и сохраните файл.
2. В Bothost обновите бота из Git-репозитория и выполните ребилд. Сохраните подключённый постоянный каталог базы и существующие переменные окружения.
3. После успешного ребилда актуальной ветки `main` отправьте `/diagnostics`. Схема базы должна оставаться **15**; номер релиза **1.0.7** указан в файле `VERSION` репозитория.
4. Отправьте `/refresh 1 2026-10-01`. Для другого завершённого дня замените дату. Команда повторно запрашивает источники даже за уже сохранённую дату; она включает отправления Ozon FBO/FBS.
5. Дождитесь итогового сообщения обновления. Проверьте строку **«Отправления Ozon · FBO/FBS»**. Значок `✅` означает успешную загрузку страниц; он не подтверждает наличие цены реализации у каждого товара. При `⚠️` сохраните сообщение обновления и результат `/diagnostics` вместе с бэкапом.
6. После завершения загрузки отправьте `/backup` и скачайте новый `.sqlite3`. Создание backup само по себе не обновляет данные API.
7. Для сверки используйте новый backup и скрин аналитики Ozon за **1 октября 2026**, где видны количество, сумма по предельной цене и сумма по цене реализации. Дополнительная платная выгрузка для проверки возвращённых полей не нужна.

Кнопки вместо команд: **«💰 Деньги и реклама» → «🔄 Обновить все отчёты»**, затем сообщение `1 2026-10-01`; backup доступен в техническом разделе владельцу системы. Для точного выбора даты удобнее команды выше.

## Что сохраняется

- Все отправления со всех страниц выбранного периода, разделённые по московской дате заказа и схеме FBO/FBS.
- Полный объект каждого отправления, включая `financial_data`, если Ozon вернул его, исходные денежные форматы, неизвестные поля, статусы и идентификаторы товаров/отправлений.
- Отметка `request_with.financial_data=true` в сохранённом исходном JSON, в том числе когда отправлений нет или финансовый блок равен `null`.
- Время проверки API и история успешных/неуспешных загрузок. При ошибке следующей страницы неполная загрузка не заменяет прошлый успешный снимок.

Технически данные находятся в `raw_payloads.payload_json`, связанные с `source_runs` для `postings/fbo` и `postings/fbs`. Новые таблицы и миграции не нужны. Данные прошлых загрузок сохраняются.

Цена покупки клиента в этом блоке пока не подтверждена на действующем аккаунте. После загрузки проверяются доступность поля для обеих схем, полнота количества, даты и сопоставление с аналитикой по товарам. Значения `price`, `customer_price`, скидки, комиссии и `payout`, если они пришли, не подменяют автоматически друг друга. Отсутствующая цена не считается нулевой.

Перевыпускать токен только из-за обновления кода не требуется. Если Ozon вернёт ошибку доступа или параметров, она будет зарегистрирована; фактическая доступность расширенных данных определяется ответом API. Сам по себе запрос не оформляет подписку.
