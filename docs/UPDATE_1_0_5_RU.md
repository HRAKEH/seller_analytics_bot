# Обновление 1.0.5

Оповещения одного магазина за один цикл проверки теперь отправляются каждому сотруднику одним сообщением. Критичные события идут первыми, восстановленные проблемы включены в ту же сводку. При большом числе событий бот показывает их количество, сокращает подробности и указывает, где открыть активные проблемы. Если событий нет, сообщение не отправляется. Настройки интервала проверки и cooldown сохраняют своё действие.

В ежедневном отчёте Ozon сумма заказов подписана как значение из аналитики API до удержаний. Начисления после удержаний сгруппированы по дате начисления и могут включать заказы других дней. Это разные наборы операций, поэтому их количества и суммы не должны автоматически совпадать. Итог начислений, комиссий, логистики и услуг рассчитывается прежним способом.

Для сверки выберите одинаковую дату начисления, кабинет и фильтры в XLSX и финансовом API. В XLSX суммируется подписанная колонка «Сумма итого, руб.» по всем строкам начислений. В API суммируется `total_amount` по всем начислениям. Для суммы заказов нужен отдельный источник: аналитика или выгрузка заказов с указанием используемого вида цены. Виджет заказов за несколько дней без точной дневной суммы не подтверждает итог финансовых начислений.

На Bothost создайте резервную копию, обновите исходники и выполните rebuild. После перезапуска откройте проверку бота и отчёт по одной загруженной дате. Новых переменных окружения и миграций БД нет, схема остаётся 15. Финансовые данные из сохранённой базы не переписываются этим обновлением.
