# Обновление 1.0.11: компактный дневной отчёт

1. Создайте backup через «🛠 Ещё» → «🧰 Техническое» → «💾 Создать backup» или `/backup` и сохраните файл.
2. Выполните rebuild из актуального `main`, сохранив каталог БД и переменные окружения.
3. Откройте «🧪 Техническая диагностика» или `/diagnostics`: версия **1.0.11**, схема **18**. Миграция выполняется автоматически со страховочной копией существующей БД.
4. Нажмите «🏠 Главное меню» → «📊 Отчёты» → «📊 Вчера». Появится короткая сводка с кнопками под ней.
5. Нажмите «Подробнее»: нижний блок появится в этом же сообщении, а кнопки заменятся одной — «Свернуть». Сверните блок, затем проверьте «Начисления».
6. Сверните блок и нажмите «Обновить». Бот запросит источники за указанную в карточке дату и заменит цифры. Дождитесь итогового статуса; при ожидании лимита API можно читать и сворачивать подробности.

Токены для обновления интерфейса менять не требуется. Для сравнения с бухгалтерией выберите нужную дату через «🗓 Другая дата», нажмите «Обновить» в полученной карточке и дождитесь завершения. После этого можно создать `/backup` для проверки сохранённых данных.

## Что означают суммы

| Место | Показатель |
|---|---|
| Верхняя сводка Ozon | Полная сумма по цене покупателя; при иностранных валютах — оценка в рублях по ЦБ на дату отчёта |
| Верхняя сводка WB | Стоимость заказов до удержаний |
| «Подробнее» | Исходные валюты и полученные цены, курс и его даты, предельная цена API Ozon, источник и время загрузки заказов |
| «Начисления» Ozon | Начисления после удержаний по дате финансовой операции |
| «Начисления» WB | `bankPaymentSum`: итог к оплате по финансовому отчёту с его периодом; отдельно — `forPaySum` за товар до остальных расходов |

Финансовые операции не обязательно относятся ко всем заказам, оформленным в выбранный день. Бот показывает фактический период отчёта WB; если его нет в сохранённом ответе, прямо сообщает об этом. Итог финансового отчёта не означает, что деньги уже поступили в банк. Себестоимость и налоги в этом блоке не вычитаются.

При неполных ценах Ozon или отсутствующем курсе бот сохраняет исходные валюты в подробностях и не выдаёт частичную сумму за полный рублёвый итог. Неполное количество по одной из подключённых площадок также не превращается в общий итог. Реальные нулевые цены и начисления отображаются как ноль.

## Доступ и поведение

- «Обновить» доступна владельцу и аналитику магазина; viewer видит две кнопки просмотра. Проверка прав действует и для вручную подставленных callback-данных.
- Карточка запоминает магазин и дату. Переключение выбранного магазина не меняет источник данных старой карточки. При отзыве доступа её кнопки не открывают данные другого магазина.
- Пока загрузка идёт, повторное «Обновить» не запускает ещё одну. Если магазин занят другой выгрузкой, бот предлагает повторить позже.
- Раскрытие блоков использует сохранённый снимок этой карточки. Фоновая загрузка и перезапуск не меняют её верхнюю сводку без явного обновления.
- Статус загрузки, успешный результат или ошибка отображаются в том же сообщении. При сбое последние сохранённые данные остаются; время их загрузки видно в блоках. Если сообщение удалено или Telegram запретил его менять, откройте новый отчёт из меню.
- Длинный нижний блок сокращается с подписью, чтобы отчёт оставался одним сообщением. Более полные отчёты и выгрузки доступны в обычных разделах меню.
- Служебные меню очищаются по правилам 1.0.10; сама карточка отчёта сохраняется. Старые сообщения без этих кнопок не переоформляются автоматически.
