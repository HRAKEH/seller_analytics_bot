# Бот с нуля: инструкция и FAQ

seller_analytics_bot · для первой самостоятельной установки · 01.10.2026

Эта инструкция рассчитана на человека, который раньше не запускал ботов. Идите по шагам. После каждого этапа есть описание результата - по нему можно понять, получилось ли всё настроить.

## Что вы получите

Свой Telegram-бот с отчётами по Wildberries и/или Ozon. Он помогает видеть заказы, известные расходы, остатки и проблемы. Бот работает на сервере: компьютер можно выключить, а сообщения продолжат приходить, пока работает хостинг.

Программа собирает данные и предлагает действия. Покупки, изменение цен и рекламные решения вы принимаете сами. Расчёт по заказам не равен подтверждённой чистой прибыли.

## Подготовьте перед началом

- Telegram и доступ к своему кабинету продавца хотя бы на одной площадке.
- Аккаунт на Bothost и рабочий тариф для запуска программы.
- Архив проекта или ссылку на его репозиторий от поставщика.
- Доступ к настройкам API своего кабинета продавца.
- Позже - таблицу себестоимости товаров и место для хранения резервных копий.

Можно начать только с одной площадки. Для первых обычных отчётов отдельный рекламный доступ Ozon не нужен.

## Пять слов простым языком

| Слово | Что означает |
| --- | --- |
| Хостинг | Компьютер в интернете, на котором постоянно работает ваш бот |
| Токен / API-ключ | Секретный пропуск: разрешает программе обращаться к Telegram или кабинету продавца |
| Переменная окружения | Настройка из двух полей: имя и значение. Например TIMEZONE и Europe/Moscow |
| База данных | Файл, в котором бот хранит историю, товары, стоимость и настройки |
| SKU | Идентификатор товара в конкретном источнике. Для импорта используйте номер из экспорта самого бота |

**Маршрут:** Telegram и ключи → хостинг → настройки магазина → 7 дней истории → себестоимость → ежедневная работа → резервные копии.

Если бот уже установлен, начните с этапа 4. Если вам выдали доступ к чужой установке как сотруднику, этапы 1-3 выполняет её владелец; ваши кнопки зависят от роли.

Источники и справка: core.telegram.org/bots/tutorial; bothost.ru/docs/; bothost.ru/docs/environment-variables; bothost.ru/docs/database-storage; bothost.ru/docs/custom-dockerfile. Документация площадок: dev.wildberries.ru; docs.ozon.ru/api/seller/. Сценарии проверены по коду версии 1.0.2, схема 15; интерфейсы внешних кабинетов могут меняться.

## Этап 1. Создайте своего Telegram-бота

1. Откройте официальный чат **@BotFather**: https://t.me/BotFather. Проверьте имя аккаунта, чтобы не попасть в похожий чат.
2. Отправьте **/newbot**. Введите название, затем уникальное имя пользователя, оканчивающееся на bot, например my_shop_analytics_bot. Если оно занято, придумайте другое.
3. BotFather пришлёт токен. Сохраните его в закрытом месте: позже он понадобится для поля **TELEGRAM_BOT_TOKEN** на хостинге.
4. Откройте созданного бота по ссылке от BotFather и нажмите «Запустить». До установки программы он может не отвечать - это ожидаемо.

Токен относится к боту. Ваш пароль Telegram, код входа и пароль кабинета продавца программе не нужны.

## Этап 1, продолжение. Ваш Telegram ID

Это номер **вашего аккаунта**, которому разрешено управлять ботом. Username вида @name, телефон, ID BotFather и номер созданного бота сюда не подходят.

Один вариант - https://t.me/userinfobot: сторонний, неофициальный сервис, показывающий сведения об аккаунте. Отправьте ему /start и возьмите свой номер **Id**. Не отправляйте этому сервису токены, пароли или коды входа. Если не хотите использовать сторонний сервис, получите свой ID выбранным вами доверенным способом.

Полученный номер сохраните для **TELEGRAM_OWNER_ID**. Число 123456789 ниже - только пример, его нельзя использовать вместо своего ID.

## Этап 2. Подготовьте доступ к маркетплейсам

### Если у вас Wildberries

В своём кабинете продавца откройте управление доступом к API и создайте один **Personal token с доступом на чтение**. Проект ожидает именно такой токен; второй Base token добавлять не требуется.

Для полного набора функций в .env.example перечислены категории: Statistics, Analytics, Finance, Promotion, Supplies, Prices and Discounts. Названия в кабинете могут быть переведены. Правильность выбранных категорий проверьте по актуальной документации WB и затем кнопкой «Проверить API». Некоторые функции могут зависеть от доступов кабинета.

Сохраните токен для **WB_API_TOKEN**. Нельзя брать ключ чужого магазина.

### Если у вас Ozon

В своём кабинете найдите раздел ключей **Seller API**. Подготовьте **Client ID** и ключ API одного и того же кабинета. Сохраните их для **OZON_CLIENT_ID** и **OZON_API_KEY**. Разрешения должны покрывать используемые функции чтения; проверка будет на этапе 4.

Для рекламы Ozon нужны отдельные ключи **Performance API**. Их можно подключить позже. Ключ Seller API не подменяет Performance Client Secret.

**Результат этапов 1-2:** у вас есть собственный бот, ваш числовой ID и ключи хотя бы одной площадки. Секреты ещё не отправлены в рабочий чат бота.

## Этап 3. Разместите проект на Bothost

1. Войдите в Bothost и создайте отдельный проект для своего бота. Используйте способ подключения кода, доступный в панели: репозиторий GitHub или импорт файлов, если он поддерживается.
2. При использовании архива распакуйте его. В корне проекта должны лежать **Dockerfile**, **main.py**, **requirements.txt** и папка **app**. Архив внутри архива или лишняя внешняя папка могут помешать найти главный файл.
3. Выберите сборку по собственному **Dockerfile**. В документации Bothost это настройка «Использовать собственный Dockerfile» в дополнительных настройках. Если панель выглядит иначе, ориентируйтесь на её актуальную справку. Команда запуска проекта - **python main.py**; внутри Dockerfile она уже задана.
4. Откройте настройки проекта → **Переменные окружения**. Добавляйте каждую строку ниже как два отдельных поля: имя и значение. Секреты подставьте свои.

| Имя | Значение или пояснение |
| --- | --- |
| TELEGRAM_BOT_TOKEN | Ваш токен от BotFather |
| TELEGRAM_OWNER_ID | Ваш числовой ID; например 123456789, но введите свой |
| DB_FILE | /app/data/seller_analytics.sqlite3 |
| TIMEZONE | Europe/Moscow, если вам нужно московское время |
| REPORT_TIME | 09:00, если отчёт нужен в 9 утра |
| WB_API_TOKEN | Ваш токен WB; только если используете WB |
| OZON_CLIENT_ID | Ваш Client ID; только если используете Ozon |
| OZON_API_KEY | Ваш Seller API-ключ; обязательно вместе с Ozon Client ID |

Для одной площадки достаточно её ключей. Не добавляйте примерные или чужие значения в пустые поля другой площадки. В поле имени вводите, например, TELEGRAM_OWNER_ID, а в поле значения - только число, без «=», кавычек и @.

Реклама Ozon подключается позже двумя полями: **OZON_PERF_CLIENT_ID** и **OZON_PERF_CLIENT_SECRET**. Остальные параметры программы на первом запуске можно оставить по умолчанию.

5. Убедитесь, что каталог **/app/data** используется как сохраняемое хранилище. Bothost описывает его как место для базы между обновлениями. На своей установке проверьте сохранность данных; на другом хостинге требуется постоянный диск.
6. Сохраните настройки и запустите проект. Дождитесь окончания сборки. Откройте **логи запуска**, затем своего Telegram-бота и отправьте **/start** из аккаунта, чей ID вы указали.

**Должно получиться:** бот отвечает и показывает главное меню. Если не ответил, смотрите раздел «FAQ: ошибки и подключение». Не создавайте второй экземпляр с тем же токеном.

## Этап 4. Настройте магазин кнопками

Откройте **Магазин → Мастер настройки**. Бот задаст шесть вопросов. Отвечайте обычным текстом, по одному ответу на вопрос.

| Вопрос | Что написать |
| --- | --- |
| Название магазина | Свой понятный вариант, например «Мой магазин» |
| Часовой пояс | Europe/Moscow для московского времени |
| Время отчёта | 09:00 или другое время в формате ЧЧ:ММ |
| За сколько дней предупреждать о запасе | Например 14. Это порог предупреждения, а не срок доставки |
| При каком падении заказов предупреждать | Например 35, то есть 35%. Подберите порог под свой бизнес |
| Порог ДРР | Например 25, то есть 25%. Это сигнал проверить рекламу, а не обещание её прибыльности |

Указанные числа - примеры, а не универсальные нормы. ДРР означает долю рекламных расходов в продажах, которые рекламный источник отнёс к рекламе.

После завершения откройте **Магазин → Настройки магазина**. Проверьте название, время и режим работы. Если указан DEMO, это учебные данные; отправьте **/demo_off**, чтобы выключить демо перед реальной загрузкой. На обычном новом запуске включать демо не требуется.

Затем нажмите **Магазин → Проверить API**. Бот проверит реальные подключения. Если источник не прошёл проверку, сначала устраните ошибку из FAQ. **Что настроено** проверяет локальные настройки и наличие данных; это другая проверка.

## Этап 5. Загрузите первую неделю

1. Откройте **Отчёты → Догрузить данные**.
2. Выберите Ozon, Wildberries или обе площадки, если обе подключены.
3. Нажмите **7 дней**. Бот загружает завершённые дни; сегодняшние данные могут быть неполными.
4. Дождитесь сообщения о результате. Если API требует долгого ожидания, нажмите **Остановить загрузку** и продолжите после указанного срока. Уже сохранённые дни останутся.
5. Откройте **Отчёты → Что уже загружено**, затем **Вчера**. Проверьте период, выбранную площадку и предупреждения.
6. Если нужна большая история, вернитесь в «Догрузить данные» и выберите 30 дней или свой период. Уже успешно загруженные дни повторно не скачиваются.

Первое заполнение может занимать время из-за ограничений площадок. Несколько нажатий подряд не ускоряют API.

**Должно получиться:** видны загруженные даты и показатели там, где площадка вернула данные. Если продаж не было, нулевые показатели возможны; если загрузка не удалась, это отдельная проблема, а не нулевые продажи.

## Этап 6. Добавьте себестоимость товаров

Бот не знает, за сколько вы закупаете или производите товар. Без стоимости прибыльность оценить нельзя. Подготовьте её за **одну единицу**, в рублях. Что включать в стоимость, заранее согласуйте со своим бухгалтером.

### Возьмите номера товаров из самого бота

После загрузки истории откройте **Ещё → Экспорт**, выберите период и Excel. Скачайте файл и откройте лист **Costs**. В нём есть marketplace и marketplace_sku; последнюю колонку используйте для **sku** в своей таблице импорта. Не заменяйте номер штрихкодом, названием или артикулом продавца.

### Сделайте таблицу Excel

На первом листе создайте четыре колонки с заголовками ровно как в примере. SKU удобно хранить как текст, без округления длинных номеров. В cost_price укажите обычное число.

| marketplace | sku | cost_price | effective_date |
| --- | --- | --- | --- |
| ozon | 123456 | 250 | 2026-09-01 |
| wb | 987654 | 320 | 2026-09-01 |

Номера и цены вымышленные. Подставьте свои товары и стоимость. effective_date - дата, с которой стоимость действительно действует, в формате ГГГГ-ММ-ДД. Не ставьте раннюю дату только ради заполнения отчёта, если тогда действовала другая цена.

Если хотите анализировать заказы за прошлую неделю, стоимость должна действовать в эти дни. **Без effective_date применяется дата импорта; на прошлые дни новая стоимость не распространяется.** При изменении цены добавляйте запись с новой датой действия.

### Отправьте файл

1. Сохраните таблицу в **.xlsx**. Если используете формулы, пересчитайте их в Excel и сохраните готовые значения. Старый формат .xls не подходит.
2. Откройте **Товары → Импорт себестоимости**.
3. Нажмите скрепку в Telegram и отправьте таблицу **файлом/документом**, а не фотографией.
4. Прочитайте результат: сколько строк применено, сколько ошибок. Исправьте указанные строки и отправьте файл снова. Успешные строки при частичном импорте уже сохранены.

Ошибка «SKU не найден» означает: сначала проверьте выбранный магазин и загрузку истории, затем сравните номер с экспортом.

Одинаковый физический товар на WB и Ozon можно связать колонкой internal_sku, но для первого запуска она не обязательна. Не объединяйте разные размеры, цвета или модели. Связь влияет на общий учёт товара и себестоимости.

**Должно получиться:** стоимость видна в данных, а в экономике товаров есть покрытие себестоимости. Если результат остаётся пустым, проверьте все продававшиеся товары и даты действия цены.

## Этап 7. Пользуйтесь ботом каждый день

### Первое знакомство с разделами

| Откройте | Что посмотреть |
| --- | --- |
| Отчёты → Вчера | Заказанные единицы и изменение относительно предыдущего дня |
| Отчёты → Неделя / Месяц | Сохранённые данные за 7 / 30 дней; «Месяц» не равен календарному месяцу |
| Товары → Топ товаров | Какие товары дают больше заказов и где есть изменение спроса |
| Товары → Остатки | Количество и дату снимка; неизвестное количество нельзя считать нулём |
| Деньги и реклама → Результат магазина | Расчёт по заказам и известным расходам; обязательно прочитайте предупреждения |
| Поставки → План поставок | Рекомендации с учётом истории, остатков и подтверждённых поступлений |
| Проблемы → Что делать сегодня | Приоритетные задачи и факты, на которых они основаны |
| Ещё → Экспорт | Таблицы для своих проверок или передачи бухгалтеру |

### Ежедневные пять минут

1. **Проблемы → Состояние данных:** посмотрите дату обновления источников.
2. **Отчёты → Вчера:** проверьте, не указаны ли неполные данные.
3. **Проблемы → Что делать сегодня:** откройте задачу, прочитайте причину и следующий шаг. Нажмите **Принято**, если взяли её в работу, или **Отложить на 24 ч**, если вернётесь позже.
4. **Товары → Остатки** и **Поставки → План поставок:** проверьте риски. Перед заказом товара подтвердите наличие, сроки прибытия, упаковку и минимальную партию.

«Принято» не лечит причину и не закупает товар. Отложенная проблема может вернуться, если условие сохраняется. Бот не меняет ставки, цены и поставки вместо вас.

### Когда нужны свежие данные

Открытие обычного отчёта читает уже сохранённую базу. Используйте **Обновить вчера**, **Обновить остатки**, **Обновить финансы** и **Обновить рекламу** в соответствующих разделах. Историю загружайте через «Догрузить данные». Фоновые процессы также обновляют данные, пока приложение работает.

Финансы и реклама обновляются **раздельно**. Для первого анализа можно начать с финансов. Если используете Ozon Performance, добавьте его ключи, примените настройки на хостинге и перезапустите приложение, затем проверьте API и рекламу.

Прогноз поставок требует истории. За первую неделю вы проверяете работоспособность загрузки, а не доказываете точность модели. Акции и самокалибровку имеет смысл изучать после накопления корректных данных.

## FAQ: данные и деньги

### Почему бот показывает больше или меньше, чем кабинет?

Сравните одинаковые даты, часовой пояс, площадку и показатель. Заказанные товарные единицы, заказы, выкупы, возвраты и выплаты - разные величины. Кабинет и API также могут обновляться в разное время. Для финансов свежие дни могут быть ещё не закрыты.

### Один заказ с тремя товарами - это три заказа?

В главной метрике бота это три **товарные единицы**. Это не означает три отдельных заказа или три выкупа. Не сравнивайте этот показатель с количеством чеков.

### Почему «Месяц» не совпадает с отчётом за сентябрь?

Кнопка показывает последние 30 дней. Для сверки смотрите точные даты в отчёте и экспорте. Сравнение периодов использует сопоставимые завершённые календарные позиции; пропуски данных влияют на полноту.

### Что означает «—»? Это ноль?

Нет. Значение неизвестно или пока не может быть рассчитано. Например, не хватает себестоимости, товара, остатка или данных API. Ноль показывается только там, где есть достаточное основание считать значение нулевым. Читайте пояснение рядом с показателем.

### «Результат магазина» - это моя чистая прибыль?

Это **управленческая оценка**: сумма заказов минус историческая себестоимость, известные расходы площадки и реклама, плюс компенсации. Заказы могут не завершиться выкупом. При неполной себестоимости результат скрывается; неизвестные комиссии и реклама требуют отдельной проверки. Полнота комиссий WB не подтверждена. Налоги, зарплата и другие расходы бизнеса учитываются отдельно.

### Как убедиться, что расчёт подходит моему магазину?

Загрузите завершённую неделю, стоимость с правильными датами, финансы и используемую рекламу. Сопоставьте одинаковые показатели с кабинетами. Перед использованием финансового результата покажите бухгалтеру экспорт и документ с формулами. Не подставляйте выдуманные расходы ради красивого итога.

### Почему есть заказы, но мало финансовых операций?

Начисления и закрывающие операции поступают позже заказов. **Проверка расхождений** помогает найти незавершённые связи. Пробел в сверке - повод проверить сроки и статусы, а не автоматическое доказательство ошибки площадки.

### Я заполнил стоимость сегодня. Почему прошлые дни всё ещё пустые?

Проверьте effective_date. Если даты нет, бот применяет дату импорта. Для старого периода нужна реальная стоимость, действовавшая тогда. Также проверьте, что заполнены все товары с заказами за анализируемые дни.

### ДРР и ROAS что-то говорят о прибыли?

ДРР = расходы на рекламу / продажи, отнесённые к рекламе × 100%. ROAS = такие продажи / рекламные расходы. Они описывают отдачу рекламы, но не учитывают все затраты магазина. При нулевом знаменателе показатель не рассчитывается; «—» не означает хорошую рекламу.

## FAQ: ошибки и подключение

### Бот вообще не отвечает. С чего начать?

Проверьте, запущен ли проект и не закончился ли доступ к хостингу. Откройте логи **запуска** после сборки. Сверьте TELEGRAM_BOT_TOKEN с токеном вашего бота, отправьте /start именно ему. Проверьте, что другая копия приложения с этим токеном не работает.

### Бот пишет «нет доступа» или не показывает нужные кнопки.

В собственной новой установке сравните TELEGRAM_OWNER_ID со своим числовым ID. Он должен относиться к тому аккаунту, из которого вы пишете. При доступе сотрудника попросите владельца назначить роль: viewer читает, analyst обновляет, owner управляет магазином. Резервные копии всей базы доступны только владельцу установки из env.

### Что означает ошибка 401?

Источник не принял авторизацию. Проверьте, не истёк ли ключ, правильно ли он скопирован и относится ли к нужному кабинету. Изменения внесите в переменные хостинга, сохраните и перезапустите приложение. Затем нажмите «Проверить API».

### Что означает ошибка 403?

Источник отказал в доступе. Проверьте тип токена, права нужной категории и доступность функции для кабинета. Повторное нажатие не добавляет прав. Для WB проверьте один Personal token с чтением и нужными категориями.

### Что означает ошибка 429? Почему ожидание такое долгое?

Маркетплейс ограничил частоту обращений и может указать длительный срок ожидания. Дождитесь срока из сообщения. Если история загружается и мешает ждать, нажмите **Остановить загрузку**. Сохранённые дни не удаляются. Перезапуск или повторные нажатия не разрешают обходить лимит площадки.

### Почему остатки WB не загрузились, а Ozon работает?

Доступ к источникам проверяется отдельно. Авторизация WB и доступ к его stock endpoints - разные проверки; у последних может быть 403. Автоматические повторения отказавших WB stock-запросов подавляются до перезапуска или успешного ручного обновления остатков. Не считать неизвестный запас нулём; проверьте его в кабинете WB.

### Нажал «Догрузить данные» ещё раз, но запросы не пошли.

Возможно, все дни уже успешно сохранены - бот не скачивает их повторно. Откройте «Что уже загружено». Для свежего вчерашнего дня существует «Обновить вчера». Если период с пропусками, проверьте сообщение о загрузке и ограничения API.

### Я потерялся в кнопках или бот ждёт непонятный ответ.

Нажмите **Отмена**, чтобы завершить ввод, затем **Главное меню**. Если клавиатура Telegram скрыта, откройте её кнопкой клавиатуры рядом с полем сообщения или отправьте /start. В повседневной работе команды помнить не нужно.

### Не пришёл утренний отчёт.

Проверьте, работает ли приложение, не заблокирован ли бот, отправляли ли вы /start, а также время и часовой пояс в **Настройках магазина**. После мастера параметры магазина хранятся в базе: смена REPORT_TIME в env сама по себе не заменяет сохранённое расписание. Проверяйте также «Состояние данных» и ошибки в техническом разделе.

## Этап 8. Сохраните данные и обновляйте бот

### Сделайте первую резервную копию

1. Откройте **Ещё → Техническое → Создать backup** из аккаунта владельца установки.
2. Бот пришлёт файл базы. Скачайте его на свой компьютер или в закрытое хранилище отдельно от хостинга.
3. Назовите копию с датой. Повторяйте перед обновлениями и после важных изменений данных.

Копия содержит коммерческие данные всей установки. Храните её закрыто и вне хостинга. Автоматические копии на том же сервере не заменяют внешнюю копию.

**Экспорт Excel** удобен для анализа и бухгалтера, но не восстанавливает все настройки и историю программы. Для восстановления нужна резервная копия базы.

### Как обновлять

Сначала скачайте backup. Затем обновите код по инструкции к выбранной версии, сохранив env, DB_FILE и /app/data. После запуска проверьте /start, выбранный магазин, загруженную историю, «Проверку бота» и API. Убедитесь, что работает одна копия приложения.

**Восстановить backup** заменяет всю базу, а не один отчёт. Данные и изменения, появившиеся после даты копии, не будут в восстановленной базе. До восстановления оцените это и выберите правильный файл.

### После обновления пусто или появился лишний магазин?

Сначала проверьте **Магазин → Список магазинов → Выбрать магазин**. Затем сравните прежний и текущий DB_FILE и сохранность каталога данных. Пустая новая база может выглядеть как новый магазин; смена пути не переносит старую базу.

Если точно найден лишний дубль в той же базе, сначала сделайте backup и архивируйте именно его. Архивирование сохраняет данные; удаление магазина стирает их. Не удаляйте базу для решения этой проблемы.

## Контрольный список: можно начинать ежедневную работу

- Бот отвечает, выбран мой магазин, демо выключено.
- Нужные площадки подключены; я вижу даты загрузки и понимаю предупреждения.
- История загружена; стоимость заполнена за нужные даты.
- Я различаю заказы, выкупы, выплаты и управленческий результат.
- Проверено время отчёта; данные пережили перезапуск.
- Backup скачан вне хостинга; контрольный период проверен по кабинетам.

Вы самостоятельно следите за хостингом, сроками ключей, стоимостью и решениями по товарам. Если площадка меняет API, программе может понадобиться обновление. Пропуски, неизвестные расходы и старые остатки требуют проверки владельцем магазина.

Если проблема не решена, сообщите поставщику версию бота, выбранный магазин, дату, действие и текст ошибки. Вопросы хостинга и прав API направляйте в поддержку соответствующего сервиса. На скриншотах скройте токены и коммерческие данные.
