# Обновление до 1.0.17

1. Создайте и скачайте резервную копию: **Ещё → Техническое → Создать backup**.
2. Сделайте ребилд в BotHost из ветки **main** репозитория [HRAKEH/seller_analytics_bot](https://github.com/HRAKEH/seller_analytics_bot). В логах должны быть версия **1.0.17** и схема **20**. Сохраните прежний путь базы и переменные подключения; токены обновлять не нужно.
3. Откройте **/start → Магазин → Сотрудники → Открыть**. Выберите человека → **Изменить роль** → **Владелец**, **Бухгалтер** или **Менеджер**. Старые владельцы не понижаются автоматически.
4. Для нового сотрудника нажмите **Добавить сотрудника**, отправьте его числовой Telegram ID и выберите роль кнопкой. Человек может узнать свой ID через **/start** даже до выдачи доступа.
5. Проверьте вход с аккаунта сотрудника: бухгалтер видит финансовые отчёты; менеджер — продажи, товары, остатки, рекламу и поставки. У менеджера в ежедневной карточке нет кнопки начислений, а экспорт содержит только рабочие сведения. Права действуют отдельно для каждого магазина.

Технические функции и управление всей установкой доступны только владельцам, указанным в **TELEGRAM_OWNER_ID** на хостинге. Если ранее туда добавляли ID обычных сотрудников, оставьте в этой переменной ID действительных владельцев всего бота и примените изменение с перезапуском. Затем назначьте сотрудникам роли через меню: изменение env само по себе не понижает уже сохранённую роль магазина.

Последнего владельца магазина нельзя удалить или понизить. Владельцев из TELEGRAM_OWNER_ID меню сотрудников не изменяет. Отзыв доступа относится только к выбранному магазину.

Схема **20** сохраняет существующие доступы и данные. Старая роль `analyst` становится `accountant`; старые `viewer` сохраняют прежний доступ на чтение. В новых кнопках предлагаются три согласованные роли. Перед миграцией автоматически создаётся страховочная копия базы.

После обновления обычные страницы, отправленные версией до 1.0.17, сотрудники открывают заново: в старых снимках отсутствовало разделение финансовых и рабочих данных. Новые страницы проверяют текущие права при каждом нажатии, в том числе после перезапуска. Ежедневные карточки проверяют доступ к начислениям отдельно.

На копии предоставленного бэкапа проверен переход **18 → 20**: данные всех 42 исходных таблиц и все четыре назначения владельцев сохранены; исходный файл не изменён. Автоматические оповещения, копируемые артикулы и перелистывание сохраняются.

Локальная проверка: **628 тестов прошли**, аудит релиза и пробный запуск проверки конфигурации на отдельной базе успешны. После ребилда проверьте меню и роли на реальных аккаунтах сотрудников.
