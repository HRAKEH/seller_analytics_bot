# Отмены Ozon: подключение и проверка

Бот принимает уведомления об отменах отправлений FBO и FBS/rFBS.
Это доступно в Start, Pro, Business и основном проекте. HTTP работает в том же процессе;
Telegram продолжает работать через long polling.

## 1. Перед обновлением

Создайте backup и сохраните его отдельно. Обновляйте тот же бот БотХоста:
сохраните токен Telegram, ключи API, постоянный том и прежний DB_FILE.
Обновление добавляет таблицы схемы 22, сохраняя прежние данные и настройки.

## 2. Домен БотХоста

1. Откройте нужного бота → «Домен».
2. Включите «Использовать свой домен». Оставьте поле своего домена пустым для автоматического HTTPS-адреса.
3. Нажмите «Сохранить» и скопируйте фактически выданный домен.
4. Добавьте переменные:

```dotenv
OZON_PUSH_ENABLED=true
OZON_PUSH_BASE_URL=https://ваш-домен.bothost.tech
HEALTH_HOST=0.0.0.0
```

OZON_PUSH_BASE_URL — только HTTPS-домен без пути, секретов и параметров.
Сервер читает внутренний порт из PORT, который передаёт БотХост.
Если уже задан HEALTH_PORT, он имеет приоритет и должен совпадать с внутренним портом панели.
HEALTH_SERVER_ENABLED для приёма Ozon не требуется: этот HTTP-сервис сам отдаёт /health и /ready.

5. Сделайте ребилд. Главный файл — main.py.
6. Откройте `https://ваш-домен.bothost.tech/health`: появится JSON; проверьте `ready: true`.
   В логах должна быть строка `Ozon push HTTP server listening on 0.0.0.0:...`.

## 3. Адрес для магазина

1. В личном чате Telegram выберите нужный магазин.
2. «Ещё» → «Техническое» → «Подключить отмены Ozon». Также доступна команда /ozon_push.
3. Нажмите «Создать адрес».
4. Скопируйте полный адрес из нового сообщения: нажмите на его текст.

Адрес содержит секрет доступа. В БД хранится только хеш, поэтому полный адрес показывается при создании.
Сохраните сообщение. Если потеряли его, подтвердите замену адреса в боте и обновите адрес в Ozon.
Замена отключает старый адрес. Перезапуск и backup/restore сохраняют действующую привязку.

В Business повторите подключение для каждого магазина: один домен, разные защищённые пути.
После смены кабинета в профиле или OZON_CLIENT_ID создайте новый адрес для этого магазина.

## 4. Кабинет Ozon

1. Откройте кабинет именно выбранного магазина.
2. Перейдите в [Push уведомления](https://seller.ozon.ru/app/settings/notifications-api).
   Путь может называться «Настройки → Уведомления» или «Настройки → Интеграции → Push уведомления».
3. Включите уведомления → «Подключить» → вставьте полный адрес из бота.
4. Нажмите «Проверить», затем «Сохранить».
5. Включите два типа:

| Тип | Какие отмены принимает бот |
|---|---|
| TYPE_FBO_POSTING_CANCELLED | FBO; время отмены — cancel_date |
| TYPE_POSTING_CANCELLED | FBS/rFBS; время отмены — changed_state_date |

TYPE_ORDER_CANCELLED не содержит состава товаров. Если его тоже присылают,
бот сохраняет его для проверки и не добавляет штуки к отменам отправлений.

## 5. Проверка

1. Откройте «Подключить отмены Ozon» заново: появится время проверки Ozon.
2. Дождитесь следующей настоящей отмены. Обновите раздел: появятся время уведомления и Seller ID отправителя.
3. Проверьте, что адрес добавлен в правильный кабинет. Seller ID из Push не предполагается равным Client-Id API.
4. Откройте дневной отчёт за дату отмены по Москве. Пример: `Отменено: ≥ 3 шт. · по уведомлениям`.
5. Для окончательной сверки сохраните backup и скрин/выгрузку отмен кабинета за тот же день.

В штуках считаются товары, а не заказы или отправления: 2 + 3 единицы дают 5 шт.
Повторная доставка не увеличивает итог. Отмена старого заказа относится к дню отмены.

## Почему итог неполный

- Уведомления начинают приходить после подключения; предыдущие дни сами не восстанавливаются.
- Доставка может прерываться. Push сам по себе не подтверждает полноту за весь день.
- Если уведомлений нет, бот показывает «отмены за день не подтверждены», а не ноль.
- «≥ N» — подтверждённая часть. Неверные поля и разные версии сохраняются для проверки; спорные количества исключены.
- В уведомлениях нет суммы отмен. Цена заказа не используется как подтверждённая сумма отмен.
- Реализация, клиентские возвраты, реклама и начисления используют отдельные источники.

## Если подключение не проходит

| Что видно | Что проверить |
|---|---|
| 502/504 или /health не открывается | Домен включён; ребилд завершился; сервер слушает 0.0.0.0; порт панели совпадает с PORT/HEALTH_PORT |
| /health работает, Ozon получает 404 | Вставлен полный адрес; он не заменён; магазин активен и запущен в этой сборке; профиль и Client ID не изменились |
| Проверка прошла, отмен нет | Включены оба типа; после подключения была отмена; Push уведомления активны в кабинете |
| seller_id не совпадает | Адрес добавлен к другому кабинету. Замените его и подключите к нужному кабинету |
| Уведомления с ошибками/разными версиями | Сохраните backup для проверки. «Обновить отчёты» не исправляет поля Push |

Ответ 200 отправляется после сохранения в SQLite. При временной недоступности БД ответ 503 позволяет Ozon повторить запрос.
Access-логи приложения отключены; заголовки и секрет адреса не записываются. HTTP-тело ограничено 256 КиБ.

Документация: [БотХост: домен и HTTP](https://bothost.ru/docs/web-apps-domains),
[Ozon Seller API: Push уведомления](https://docs.ozon.ru/api/seller/#section/Push-uvedomleniya).
