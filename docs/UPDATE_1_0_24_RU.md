# Обновление 1.0.24: резервные копии занимают меньше места

Эти возможности входят во все тарифы бота: Start, Pro и Business. Переходить на более дорогой тариф бота или хостинга для их включения не нужно.

| Что изменилось | Как работает |
| --- | --- |
| Копии на сервере | Хранятся в ZIP с одним файлом SQLite; при ошибке сжатия остаётся проверенная SQLite-копия |
| Старые копии | Бот сжимает их после проверки базы и SHA-256, затем обновляет путь и размер в истории |
| Срок хранения | По умолчанию 7 дней |
| Количество и место | До 10 управляемых файлов и до 512 МиБ суммарно |
| Защита данных | Хотя бы одна исправная копия остаётся, даже если она старше или больше лимита; используемые файлы защищены |
| История backup | Показывает количество, размер копий и отметку о файлах, удалённых очисткой |
| Восстановление | Принимает прежние SQLite и новые ZIP; страховочная копия тоже может быть ZIP |

## Что сделать

1. Сохраните последнюю исправную резервную копию вне хостинга.
2. В переменных существующего приложения укажите:

```env
BACKUP_COMPRESS=true
BACKUP_RETENTION_DAYS=7
BACKUP_MAX_COUNT=10
BACKUP_MAX_TOTAL_MB=512
```

3. Выполните ребилд из этого репозитория, ветка `main`. Сохраните прежний `DB_FILE` и постоянный каталог `/app/data`.
4. После запуска дождитесь обслуживания хранения. Бот выполняет его при старте и каждый час, даже если автоматическое создание копий выключено. Первое сжатие старых файлов может занять несколько минут.
5. Откройте **Ещё → Техническое → История backup**, затем **Создать backup**. Сохраните полученный ZIP отдельно от хостинга.

Если новые переменные отсутствуют, применяются значения по умолчанию. Существующее `BACKUP_RETENTION_DAYS=14` само не изменится: для 7 дней замените его на `7`.

Очистка касается только файлов бота `sellerbot_…` и `pre_migration_…` в каталоге `backups` рядом с БД. Основная база, личные файлы и символьные ссылки не удаляются. Предпочтение отдаётся одной автоматической копии на каждый день. При невозможности проверить копию или завершить сжатие бот сохраняет исходный файл и пишет причину в лог; лимиты могут временно превышаться. Фактическая экономия зависит от содержимого базы — её видно после обработки в истории копий.

Схема БД остаётся **21**. Сам бэкап не заменяет независимую копию вне сервера. Восстановление через Telegram: отправленный файл до 20 МБ, база внутри ZIP до 200 МиБ; для более крупных копий нужен файловый доступ к серверу.
