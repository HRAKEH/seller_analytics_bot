# Обновление 1.0.22: резервные копии

## Что исправлено

Ошибка `Request Entity Too Large` возникает при отправке большого файла в Telegram. Создание SQLite-копии выполняется раньше; теперь бот отдельно сообщает о неудачной отправке и показывает путь к сохранённому оригиналу.

Копии больше 20 МБ бот пытается сжать в ZIP. В архиве один SQLite-файл, его содержимое не изменяется. Оригинал остаётся в каталоге `backups` рядом с рабочей базой. ZIP временный: после попытки доставки он удаляется, оригинал хранится по прежним правилам. Если и ZIP не помещается, копию скачивают через файловый доступ хостинга по пути из сообщения.

Обычный Telegram Bot API позволяет отправлять документы до 50 МБ, но скачивать для восстановления — до 20 МБ. Бот оставляет запас и отправляет файлы до 45 МиБ. Если отправленный файл больше 20 МБ, подпись предупреждает, что через `/restore` он не восстановится. Подробности: [официальная документация Telegram](https://core.telegram.org/bots/api#sending-files).

## Как обновить

1. Сохраните последнюю резервную копию вне хостинга. Если текущая версия написала `Backup не создан` после `Request Entity Too Large`, проверьте историю копий и каталог `backups` рядом с `DB_FILE`: копия могла сохраниться до ошибки отправки.
2. Выполните ребилд существующего приложения из этого репозитория, ветка `main`. Сохраните прежние переменные, `DB_FILE` и постоянный каталог `/app/data`.
3. После запуска откройте **Ещё → Техническое → Создать backup** или отправьте `/backup` из аккаунта владельца установки.
4. Скачайте полученный SQLite/ZIP. Если вместо файла бот покажет путь, скачайте указанный SQLite-файл через файловый доступ хостинга. Не скачивайте рабочую базу вместо готовой копии при работающем приложении.

Схема остаётся **21**; токены для этого обновления менять не требуется.

## Как восстановить сохранённый ZIP

**Для проверки используйте отдельный тестовый бот.** Восстановление заменяет все магазины и настройки установки состоянием на дату копии.

1. Из аккаунта владельца откройте **Ещё → Техническое → Восстановить backup** или `/restore`.
2. Отправьте сохранённый ZIP с одним SQLite-файлом, либо сам SQLite-файл. Загрузка выбранного файла запускает восстановление; чтобы выйти без замены, нажмите **Отмена** до отправки файла.
3. Отправленный файл должен быть до **20 МБ**, база внутри ZIP — до **200 МиБ**. Архивы с паролем, несколькими файлами или вложенными папками не принимаются.
4. Бот проверит файл, создаст страховочную копию и восстановит базу. Дождитесь сообщения об успешном завершении, затем проверьте магазин и отчёты.

Большие копии требуют восстановления через файловый доступ к серверу при остановленном приложении с предварительным сохранением текущих данных. Не подменяйте рабочую базу на ходу и не удаляйте историю ради уменьшения backup.
