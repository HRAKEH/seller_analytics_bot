# Обновление 1.0.12: сверка цены выкупа Ozon

1. Сохраните текущий backup через `/backup`.
2. Сделайте ребилд и перезапуск Bothost из ветки `main`.
3. Проверьте `/diagnostics`: версия **1.0.12**, схема **18**.
4. Отправьте `/day 2026-10-01`. Эта команда создаёт дневную карточку и обновляет все её источники, включая выкупы Ozon. Дополнительно нажимать «Обновить» сразу после команды не требуется.
5. Откройте «Подробнее» → «Сверка выкупов Ozon». Проверьте отправление **0225557127-0029-1**, SKU **4449497713**: появилась ли цена выкупа и какая валюта указана.
6. Создайте новый `/backup` и передайте SQLite-файл для сверки с кабинетом. Если отправление пока отсутствует в отчёте, исходный пустой ответ или причина ошибки тоже будут в базе.

Можно обновлять существующую карточку за 1 октября её кнопкой «Обновить». `/refresh 1 2026-10-01` тоже загружает выкупы, вместе с остальными отчётами.

## Что теперь можно проверить

Отчёт о выкупленных товарах — отдельный источник финансовой цены. Номер отправления, SKU и количество должны совпасть с исходным списком заказов. Имя товара или похожая сумма не считаются достаточным совпадением. Отчёт имеет собственный финансовый период: дата его строки не подменяет дату оформления заказа.

По заказу из скрина известны 750 ₽ по предельной цене, 14,98 BYN по цене покупателя и 345 ₽ по цене реализации в кабинете. В ранее присланном ответе отправлений поля с 345 ₽ не было. На момент выпуска живой ответ нового метода по этому заказу не получен, поэтому 345 ₽ не подставляется в расчёт заранее.

Чтобы решить, можно ли использовать цену выкупа вместо валютного пересчёта в сумме реализации, нужны совпадение с 345 ₽, подтверждение валюты и проверка остальных заказов/статусов дня. Если валюта отсутствует в ответе, бот пишет об этом и не назначает рубли по умолчанию. Основная сумма по цене покупателя и оценка по ЦБ сохраняют своё прежнее основание.

## Период поиска и ошибки

Для выбранных заказов загружаются финансовые даты от начала выбранного периода до текущего дня, максимум 60 дней после конца периода. Запросы разбиваются на окна до 31 дня. Ограничение поиска не гарантирует, что все выкупы появятся за это время; если цены ещё нет, повторите обновление позднее. Снимок хранится один раз на обновление и доступен для каждого дня выбранного периода.

Пустой успешный ответ означает, что строк пока нет, а не что цена равна нулю. Неверный формат ответа сохраняется для проверки с признаком неполноты. При 401/403/429 или другой ошибке предыдущие цены сохраняются с предупреждением; основной отчёт о начислениях продолжает работать независимо.

Официальный метод: [Ozon — как работать с выкупами в Seller API](https://dev.ozon.ru/start/408-Kak-rabotat-s-vykupami-v-Seller-API/). Его существование также подтверждено в [официальных уведомлениях Ozon Seller API](https://t.me/ozonsellerapi/675). Полную страницу документации во время проверки получить не удалось из-за цикла перенаправлений; исходный живой ответ сохранится для проверки контракта без потери неизвестных полей.
