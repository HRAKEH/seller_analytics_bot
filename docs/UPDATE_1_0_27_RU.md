# Обновление до 1.0.27

## Что исправлено

- Реклама Ozon по товарам получает ID всех кампаний за период, в том числе остановленных. Запросы SKU отправляются партиями; пустой список не уходит в API.
- Сохраняются исходные рекламные ответы и сведения о запросах без OAuth-секретов. Ошибка разбора сохраняет ответ для диагностики и прежние успешные данные.
- Поддержано поле расходов moneySpent. Отсутствующие, пустые и некорректные денежные поля не превращаются в ноль. Подтверждённый ноль и полный пустой ответ обрабатываются отдельно.
- Исторические расходы Ozon без исходного ответа отмечены как неподтверждённые в рекламе, выгрузке и управленческой оценке. Начисленная реклама из финансовых источников сохраняет свою отдельную базу.
- Повторная загрузка не удваивает расходы. Полный новый снимок заменяет прежние значения, включая старые записи другого рекламного источника; сбой партии SKU сохраняет прежний полный снимок.
- Оперативный метод SKU ограничен сегодняшним и предыдущим днём. Более старые данные берутся из сохранённого архива с пояснением; расходы по кампаниям загружаются за выбранный период. Ограничение истории не запускает бесконечные повторные попытки.
- Ошибки фоновой рекламы показывают конкретную причину вместо advertising retry remains partial. Схема БД остаётся 21, новые переменные не нужны.

## Как применить

1. На BotHost обновите код из Git и сделайте ребилд в текущем приложении.
2. Сохраните прежние переменные, DB_FILE и постоянный каталог данных. Переносить БД не нужно.
3. Откройте главное меню бота заново. Нажмите «Обновить рекламу» и выберите «Вчера».
4. Откройте «Реклама» за тот же период. При неполных данных видна причина; неизвестные расходы не обозначаются как 0 ₽.
5. Создайте свежий бэкап для проверки полученных ответов. Для сверки с кабинетом нужен его скрин с тем же периодом и видом расходов.

В тарифных сборках реклама доступна в Pro и Business. Start сохраняет свои прежние ограничения.

## Что остаётся ограничением Ozon

- Выкупы по текущему дневному отчёту реализации требуют доступа Premium Plus. Подписка Ozon и тариф бота — разные вещи.
- В проверенном бэкапе отправления не содержат даты отмены. Точный итог отмен за день пока не подтверждён.
- Для следующего этапа изучены типы Push API об отмене отправления FBO и заказа. Подключение потребует проверки принимающего URL на хостинге и формата события. Приём таких уведомлений в этом релизе не внедряется.
- Полнота SKU за прошлые даты зависит от ранее сохранённого архива. Отсутствующий архив не заменяется нулём.

## Проверка

Автоматические проверки охватывают корректный состав запросов, сохранение ответов, неизвестные суммы, настоящие нули, частичный сбой партии, повторные загрузки, замену старого снимка и ограничения архива. Продуктивные запросы выполняются после вашего ребилда; фактические расходы подтверждаются новым бэкапом и кабинетом.
